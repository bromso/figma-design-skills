# Listing: /build-views

## Tagline

Composes one real screen from your existing components and tokens.

## Description

Composes the screen, page, or view you ask for out of existing component instances — never redrawn shapes — with auto layout on every container whose children relate, real content instead of lorem ipsum, type and spacing pulled from tokens rather than arbitrary values, and exactly one hero element per screen.

Use it on its own when you want one screen done well — "compose the account settings screen from our existing components." It discovers what components and tokens already exist first, and if the request is really several screens, it says so and points you at `/design-brief` instead of quietly building a whole flow.

Standalone domain skill — not part of the four-command sequence, though its full rules are also the condensed ones `/design-build` carries for its views step.

Defaults to Standard depth when there's no Spec to read a Budget mode from; reads Budget from the Spec when one exists.

Typical cost: to be recorded after testing.
